# 网页采集配置管理工具

离线版采集配置管理工具，涵盖站点管理、抽取模板编排、代理池配置、限速策略、重试机制、增量采集与数据落盘规则，所有配置持久化到浏览器本地存储。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `scraper-config-studio:entries` 这一项，或调用 `resetModule(模块)`。

## 数据清洗批次

数据清洗有三层边界，读数据时按这个顺序定位：

1. **清洗规则**（`cleanse` 模块行）：一行一条规则，`去重键列` 与 `规则版本` 决定去重口径。
   种子数据里 `CLEA-74` 为已启用规则，去重键列是 `手机号`。
2. **批次**（`src/data/cleanse-service.ts`，localStorage 键 `scraper-config-studio:cleanse-batches`）：
   导入原始记录时创建，规则版本与去重键列在此刻**快照**，之后规则升版不影响已有批次。
   批次按 `processedRows` 游标分块处理（默认每轮 50 行），中断后从游标继续。
3. **键表 / 结果**：键表只记录本批次被删除的后续重复行（来源行号、首条行号、规则版本）；
   结果只保留首条及其之后不重复的行。

去重口径：

- 相同键**只删除后续重复**，首条永远保留。
- 去重键集合按「规则 + 规则版本 + 去重键列」分域，只存 `键 → 首条来源`，不存整行，
  因此记录变多时不会一次装载全部历史键。
- 同一份原始记录（同规则 + 同内容摘要 + 同版本）重复导入只建一个批次；
  同一份结果文件（同内容摘要）重复上传只生效一次。
- 版本升级时先快照旧版映射再改写映射清单的 `清洗版本`，历史结果按快照版本仍可读。

样例在 `samples/cleanse/`：两批原始记录与第二批的预期键表。键表三行来源为 2、4、7，
键分别是 `13800001111`、`13800001111`、`13900002222`，版本均为 `CLEA-74`。
